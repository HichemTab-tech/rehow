# ADR 0011: Bounded YAML Semantics and Lossless Span Edits

- Status: Accepted — Architect, Reviewer, and Security Reviewer closure passed 2026-09-06
- Date: 2026-09-06

## Context

Rehow must accept a bounded YAML 1.2 core value domain, reject ambiguous/hostile constructs, retain unknown metadata semantically, and preserve untouched source bytes across safe edits. A semantic deserializer cannot preserve comments, ordering, quoting, BOM, line endings, or final-newline state. A presentation parser alone does not enforce Rehow's semantic restrictions or resource limits. Writing a complete YAML parser/CST would add unnecessary security and maintenance risk.

## Decision

### Dependencies and isolation

Phase 1C introduces exactly `saphyr-parser = "=0.0.12"`, `yaml-edit = { version = "=0.3.1", default-features = false }`, and `rowan = "=0.16.1"` as private `rehow-core` dependencies after lockfile review. `saphyr-parser` supplies streaming semantic events. `yaml-edit` supplies a fallible presentation tree. Its required `rowan` version supplies the non-re-exported `rowan::ast::AstNode` trait and read-only root/node/token traversal needed to inspect complete syntax and obtain candidate byte ranges. Neither parser alone decides acceptance, mutation, or resource behavior; Rehow requires both accepted parses plus its own source-policy, semantic, reconciliation, and limit checks.

All three dependencies are pinned pre-1.0 surfaces behind private adapters. Any version change repeats malformed-input, preservation, API-surface, and security review. The disabled `yaml-edit` default `binary` feature is not needed because tagged/binary YAML is outside the accepted core schema. The presentation adapter may call only `YamlFile::parse` on an already size-bounded in-memory `&str`, `Parse::positioned_errors`, `Parse::tree`, `rowan::ast::AstNode::syntax`, and read-only `SyntaxNode`/`SyntaxToken` kind/text/range/parent-child traversal. After checking that a node has `SyntaxKind::SCALAR`, it may additionally call `<yaml_edit::Scalar as rowan::ast::AstNode>::cast`, then the read-only `Scalar::value` and `Scalar::as_string` methods. It immediately copies the raw and decoded strings into its bounded Rehow-owned record and drops the wrapper. These decoder results are a presentation-side reconciliation oracle only: they never select a semantic type, make invalid syntax acceptable, or override Saphyr/Rehow core resolution. Concatenated leaf token text must cover the complete parser slice exactly once in order. Path/file/relaxed parse APIs, crate I/O, builders, serializers, green-node construction, `splice_children`, `Scalar::set_value`, and every other high-level or mutation API are forbidden. The adapter copies only checked primitive span/kind/comment records into a Rehow-owned immutable artifact and drops every interior-mutable `YamlFile`/rowan handle before planning an edit.

### Frontmatter envelope

A Rehow-owned bounded byte scanner runs before UTF-8 decoding or YAML parsing. Every whole-file limit includes every byte, including a BOM. Every managed YAML slice must be UTF-8, may use LF or CRLF consistently, and rejects bare CR or mixed YAML/envelope newline style. Final-newline presence is retained.

For a Guide, the 2 MiB limit covers the complete file and the 256 KiB frontmatter limit covers byte zero through the mandatory blank separator line inclusive. Its YAML parser slice excludes the BOM, opening/closing delimiter lines, and separator line:

- accept an optional UTF-8 BOM only at byte zero;
- opening and closing delimiter lines are exactly `---`;
- require exactly one blank separator line after closing frontmatter;
- stop at the 256 KiB frontmatter cap and never search beyond the 2 MiB Guide cap;
- distinguish missing opening/closing delimiter, extra YAML document material, invalid UTF-8, and missing separator with stable diagnostics.

For the manifest and Category descriptor, the 256 KiB whole-file limit applies before removing an optional byte-zero BOM for the parser slice. They contain exactly one implicit mapping document and no YAML directive or document-marker syntax. The Guide body begins after its one blank separator line. Compare proposed body bytes with the current exact body before planning a write. A no-op save returns the unchanged document/revision and preserves timestamps and tested status. When body bytes differ, the save never reserializes frontmatter, but it must also replace `updated_at` and, for a previously tested Guide, replace `status` with `stale`. Those mandatory companion metadata edits must pass the same span checks; otherwise the entire save is refused and every byte remains unchanged.

### Presentation and source-policy preflight

Before semantic exposure, call only `yaml_edit::YamlFile::parse` on the bounded parser slice and collect every positioned error. Any positioned error, incomplete token coverage, extra document/root, or syntax node that cannot be classified is a malformed document, not a read-only round-trip warning. Walk every scalar token/node range in encounter order using checked rowan byte offsets and reject a raw scalar source range above 64 KiB before constructing Saphyr; exact-limit and one-over cases include block/flow/quoted/plain scalars and multibyte text.

Rehow owns a token/CST inspection policy over the original syntax. All directives are rejected, including `%TAG`, `%YAML 1.1`, and `%YAML 1.2`. All local, verbatim, custom-handle, and literal standalone `!` tags are rejected. The only explicit tag spellings accepted are the literal built-in shorthands `!!null`, `!!bool`, `!!int`, `!!float`, `!!str`, `!!seq`, and `!!map`, with no intervening presentation variation; the tag must apply to the node kind and scalar content must match its YAML 1.2.2 core grammar. This rule is based on original tokens, never `Tag::is_yaml_core_schema()` or a resolved handle, so a custom handle mapped to a core URI and a remapped `!!` handle cannot pass. Tags/directive-looking text inside a scalar or comment is classified by the lexer and is not rejected as syntax. Resolved strings containing a Unicode noncharacter (`U+FDD0..U+FDEF` or any scalar ending in `FFFE`/`FFFF`) are invalid. U+FEFF is valid string data only when source-escaped; a raw byte-zero occurrence is consumed as the optional document BOM, and a raw occurrence elsewhere is invalid.

### Bounded semantic pass

Feed only the preflight-accepted YAML parser slice to `saphyr_parser::Parser::new_from_str` with its standard `keep_tags(false)` behavior and consume `next_event()` incrementally; do not call recursive `Parser::load`. The non-standard cross-document tag-retention mode is forbidden. A Rehow-owned iterative frame stack enforces the limits in `docs/content-model.md` while consuming events and aborts before accepting depth 17, mapping entry 257, sequence entry 2,049, node 20,001, or scalar byte 65,537. Require exactly one mapping-root document.

Reject every alias event and every nonzero anchor ID. Reconcile each emitted tag with the already-approved source tag token; a mismatch is malformed. Rehow—not either dependency—owns YAML 1.2.2 core resolution. Plain scalars use exactly the core-schema regular expressions in section 10.3.2; non-plain scalars without an explicit source tag resolve as strings, sequences, or mappings by node kind. YAML 1.1 numeric separators and legacy booleans therefore remain strings, and timestamp-like scalars remain strings. Null, Boolean, integer, float, string, sequence, and mapping values build the parser-neutral semantic model in `docs/content-model.md`.

Depth is the number of simultaneously open collection frames, with the required root mapping at depth 1. A node is each scalar event, mapping start, or sequence start, including parser-generated empty/null scalars. A mapping entry is counted when its complete key/value pair closes; a sequence entry is counted when its complete child value closes. Decoded scalar size is its UTF-8 byte length and is checked immediately after each Saphyr event; reject above 64 KiB. Raw source size was already enforced from the presentation byte range before this pass. Saphyr marker indices are never interpreted as byte offsets. The prior 256 KiB parser-slice limit additionally bounds parser allocation. Whole-input limits are enforced before either parser allocation.

The semantic pass constructs the exact opaque-wrapper/private-representation shapes frozen in `docs/content-model.md`: `UnknownMetadataEntry`, `UnknownYamlValue`/`UnknownYamlValueRepr`, `UnknownYamlMappingEntry`, `UnknownYamlScalar`/`UnknownYamlScalarRepr`, `CanonicalYamlInteger`, and `CanonicalYamlFloat`/`CanonicalYamlFloatRepr`. Phase 1B defines those parser-neutral types, read-only accessors, and document-builder validation over already resolved values; it adds no product aggregate records, YAML parser, serializer, CST, TypeScript, or Serde representation.

Integer normalization removes sign/radix markers and leading zeroes into arbitrary-precision base-10 digits. Decimal input is normalized in one linear pass. Octal/hex input uses a Rehow-owned left-to-right multiply/add over a least-significant-first base-10 digit vector; no bigint or unmetered string-to-number conversion is allowed.

Numeric-work acceptance uses an algorithm-independent closed-form charge, not implementation operations. For one numeric scalar, let `S` be the exact count of base-radix source digits in its accepted source spelling: `[0-9]` for decimal integer, mantissa, and exponent digits; `[0-7]` for octal; and `[0-9A-Fa-f]` for hexadecimal. Sign, radix prefix, decimal point, and exponent marker/sign are excluded. Thus every hexadecimal letter is one source digit and contributes to both the linear and quadratic terms. Let `C` be the exact count of stored canonical ASCII decimal digits it would contribute: integer magnitude digits, or finite-float coefficient plus exponent magnitude digits; infinity and NaN contribute zero. Let `R = S * S` for an octal/hex integer and zero otherwise. Its charge is exactly `R + 4 * S + 4 * C`, with every multiplication/addition checked. For radix integers, charge/check `R + 4 * S` before conversion and abort without conversion when it exceeds the remaining budget; charge `4 * C` before retaining the result. Decimal integer and finite-float algorithms must be linear in `S + C`. The quadratic radix term conservatively bounds the required decimal-vector conversion while making acceptance independent of carry patterns, scan order, provisional zeroes, or implementation choice.

A per-document budget permits exactly 16 Mi (`16 * 1024 * 1024`) numeric-work units and 80 KiB (`80 * 1024`) total stored canonical numeric digits. The sum includes every numeric scalar, including numeric values nested in complex keys and both coefficient/exponent components through `C`. Reaching either limit is accepted; a scalar whose complete checked charge or retained digits would exceed the remaining budget is rejected with `yaml_numeric_work_limit`, and no partial scalar/tree is returned. Any optimized implementation must compute the identical `S`/`C`/`R` charge.

Every accepted integer zero, including negative-zero spellings, is `{ negative: false, digits: "0" }`. Finite-float normalization concatenates decimal mantissa digits, subtracts fractional width from the explicit exponent, removes coefficient leading zeroes, then removes coefficient trailing zeroes while increasing the exponent. A nonzero coefficient has no leading or trailing zero. Positive float zero has a positive sign and zero coefficient/exponent; negative float zero retains its negative sign. Exponents use `CanonicalYamlInteger`, so this process never narrows through `f64` or a machine integer. Infinities retain their sign and every accepted NaN spelling maps to `NaN`. Timestamp-like untagged scalars remain strings.

Mapping keys may be complex semantic values. Duplicate detection uses recursive, tag/type-aware key equality after normalization: alternate spellings within one scalar type compare by canonical value; integer and float remain distinct; positive and negative floating zero compare equal; all NaNs compare equal; sequences are order-sensitive; mappings are entry-order-insensitive even though their original encounter order is retained. Every mapping rejects a duplicate before construction; no hash implementation may silently replace one. Top-level extension names must resolve to strings, while nested extension mappings retain complex keys.

More exactly, null equals null; Booleans compare by value; strings compare by their exact Unicode scalar sequence with no normalization; canonical integers compare by sign/digits; finite floats compare by canonical numeric value with signed zero equal only for duplicate-key detection; infinities compare only when their signs match; and all NaNs compare equal for duplicate-key detection. Explicit and implicit core tags producing the same scalar type/value compare equal. Distinct scalar types never compare equal. Mapping equality compares the set of recursively equal key/value pairs independent of encounter order; duplicate-free construction makes this unambiguous.

Equality work is deterministic and bounded. Construct the injective, recursively framed duplicate-key encoding described by the unknown-value canonical codec in `docs/content-model.md`, using key context throughout the whole complex key so floating signed zero normalizes recursively. Compute each occurrence bottom-up once and cache it; mapping encodings sort their cached key/value pairs, so encounter order does not affect the result. Exact encoding equality is semantic key equality and detects duplicates without repeated recursive matching.

A per-document work meter allows exactly 8 MiB (`8 * 1024 * 1024`) of cached canonical-key encoding bytes and 32 MiB (`32 * 1024 * 1024`) of comparison byte-read units. Appending each byte—including tag, framing, count, and recursively copied child bytes—to any retained occurrence encoding charges one cached-encoding byte before the append. Every mapping uses the same bottom-up stable merge sort over pair records, ordered lexicographically by cached key encoding and then cached value encoding; merge widths are `1, 2, 4, ...`, the left record wins equality, and each mapping performs a final adjacent-key scan for duplicates. A lexicographic comparison charges two comparison units for every byte position read from the two operands, stops at the first unequal pair, and uses cached lengths without a charge when one equal prefix ends. Key/value sort comparisons and the final adjacent-key comparisons share the same checked document meter. Moving record handles and comparing cached lengths cost no units. Reaching either limit is accepted and the next unit is refused with `yaml_semantic_work_limit`; no partial map/tree is returned. Implementations may optimize storage or sorting only when they preserve this reference ordering and compute the identical acceptance count. Unmetered standard sorting, all-pairs matching, and implementation-dependent counters are forbidden. These caps are additional to the node/scalar/input limits.

The merge-key policy is syntax-aware. Reject the plain, untagged mapping-key scalar `<<` and every explicit merge tag (which is outside the allowlist). Quoted `"<<"`, `'<<'`, or literal `!!str <<` is an ordinary string key and participates in normal duplicate detection.

### Presentation pass and reconciliation

After semantic acceptance, reconcile the existing preflight tree with the semantic event tree. Phase 1C requires a generic bijection in encounter order matching node kind, parent/child relationships, child arity, decoded pre-resolution scalar text, scalar style, and approved source-tag surface. For a concrete scalar, copied `Scalar::value()` must equal the exact original UTF-8 text in that scalar node's checked rowan source range; only copied `Scalar::as_string()` is compared with the corresponding Saphyr decoded pre-resolution scalar. A mismatch after otherwise valid parses marks the document non-round-trippable and every mutation returns `UNSAFE_ROUND_TRIP`; neither presentation result is semantic authority.

The one exception is `yaml-edit` 0.3.1's exact representation of a source-omitted key, value, or sequence item: a zero-width `SCALAR` node containing exactly one zero-width `NULL` token with empty text at an unambiguous CST child site. When the structurally corresponding Saphyr event is its synthetic implicit-null scalar text `~`, Rehow records a dedicated implicit-empty node and bypasses ordinary `value`/`as_string` equality. It never treats an explicit source `~`, quoted empty string, nonzero range, or any other null spelling as implicit empty, and the record never supplies a replacement span. Unrelated safe edits may remain round-trippable while preserving the zero-width child byte-for-byte.

Phase 1C retains only Rehow-owned generic node kind, decoded key/scalar, candidate byte range, parent/child, style/tag, implicit-empty, and comment correspondence. It does not classify root keys as known or create mutation authority. After Phase 1D validates a product aggregate, its typed binder derives the known-field value spans, complete block-map entry spans, and unambiguous insertion/removal sites from that generic artifact. Require a no-op full-slice rendering equal to the original parser-slice bytes.

Every candidate range must be aligned to UTF-8 byte boundaries, remain within the parser slice, be contained by its reconciled parent, and be disjoint from siblings except for containment. `saphyr-parser` marker/span indices are character-count based and are never used for slicing or splicing. Only checked `yaml-edit`/rowan byte ranges may become edit ranges; Rehow rebases them to original-file byte offsets with checked arithmetic across the optional BOM and Guide envelope. Parser disagreement after two otherwise accepted parses, missing/overlapping ranges, normalization on no-op render, unsupported presentation, or ambiguous comment ownership does not invalidate safe read-only semantic access. It marks the document non-round-trippable; every metadata mutation returns `UNSAFE_ROUND_TRIP` without changing bytes.

### Authorized span edits

Metadata changes create a sequence of validated, pairwise non-overlapping edits in original-file byte coordinates. Adapters supply typed mutation intent and validated domain values only; they can never supply YAML source/fragments or edit ranges. Every replacement/insertion payload is produced internally by the same Rehow-owned deterministic fixed-schema value emitter used for new documents. Rehow does not invoke `yaml-edit` high-level mutation or YAML serialization for existing content. The only edit forms are:

- `ReplaceValue(range, bytes)` for one reconciled known-field value range. Replacing a whole collection is allowed only when it contains no unknown descendant and the declared effect set includes every descendant change; otherwise edit reconciled child ranges or refuse;
- `InsertField(site, bytes)` for a zero-width, unambiguous block-mapping site and one complete deterministically emitted field (contiguous fields at one site are ordered and coalesced before application);
- `RemoveEntry(range)` for one complete block-mapping entry range, including exactly the line ending it owns. For a final entry without a following line ending, the range may include its preceding line ending only when that line ending and both neighboring entries are unambiguous.

Insertion and removal are refused for flow mappings, ambiguous indentation/newlines, or any entry/site with an owned or ambiguously adjacent comment. Clearing a sole `settings.default_category_id` removes the complete `settings` entry when it has no other known/unknown children; otherwise it removes only the nested entry. Canonically emitted documents must expose safe sites for paired archive-field insertion/removal and default-Category insertion/removal.

The fixed-schema emitter uses the established LF/CRLF style and two spaces per nested block level. A new document uses UTF-8 without BOM, LF, and one final LF; a new Guide also uses the exact delimiter and blank-separator envelope above. Known ASCII field names are plain. Validated integer values are canonical base-10 plain scalars; Booleans are lowercase; fixed lowercase enum tokens are plain; null is never emitted for omission. Every domain string—including UUIDs, timestamps, URLs, and user text—is double quoted: a double quote is prefixed by one reverse solidus, a reverse solidus is doubled, and C0/C1, DEL, `U+061C`, `U+200E`, `U+200F`, `U+2028..U+202E`, `U+2066..U+2069`, and `U+FEFF` use one reverse solidus, lowercase `u`, and exactly four uppercase hexadecimal digits. Unicode noncharacters were rejected by domain validation; all other Unicode scalar values remain UTF-8. Sequences/mappings use block style in schema field order, one item/entry per line; an empty collection uses `[]` or `{}`. Existing flow collections are never replaced wholesale. Unknown extension entries have no generic emitter or mutation API in v1; they are preserved, not regenerated.

- Copy every untouched byte directly from the original.
- Refuse replacing a collection/value that contains or ambiguously owns a comment.
- Apply ranges from highest offset to lowest.
- Reparse/revalidate the complete candidate through both passes.
- Construct an exact declared semantic effect set before editing, including core-owned `updated_at`, status, and archive/default-Category companion changes. After reparsing, require the complete candidate semantic tree to equal the original tree with exactly that effect set applied. Every unknown metadata entry/descendant must remain semantically identical unless that specific unknown entry is itself an explicitly authorized user edit; a known parent replacement cannot implicitly authorize dropping it. Any undeclared delta refuses the complete operation.
- Prove byte correspondence outside edits before any storage write: remove inserted candidate bytes and reinsert removed original bytes, then require exact equality with the original outside replaced ranges.

New documents use this deterministic Rehow emitter for the fixed schema, not a general YAML serializer. Before storage, every new emitted document is parsed through both passes and must equal its complete intended semantic tree; failure produces no file. The storage/revision layer remains responsible for atomic durable writes; this ADR only produces validated candidate bytes.

## Semantic model boundary

The parser-neutral unknown-value tree preserves semantic values, sequence order, mapping membership, complex keys, and deterministic encounter order. It does not contain comments, directives, source spelling/style, whitespace, BOM, line endings, or source offsets and never claims byte preservation. Existing content retains original bytes plus the private presentation/span artifact. Phase 1B may define and test the semantic types but must not define product aggregate records or parse or serialize Workspace content. Phase 1C adds only the generic parser/reconciliation artifact; the typed aggregate/emitter/span-edit layer follows the separate Phase 1D schema gate in `docs/implementation-plan.md`.

## Required evidence

- Exact-limit and one-over tests for every byte/depth/map/sequence/node/scalar cap, with prompt termination and no panic.
- Invalid UTF-8; BOM placement; whole-file/frontmatter boundaries including the BOM and mandatory separator; LF/CRLF/bare CR/mixed newlines; delimiter; blank-separator; and multiple-document cases.
- Unused `%TAG`; custom handles mapped to core URIs; `!!` remapping; every `%YAML` version including 1.2; reserved directives; anchors on every node kind; aliases; merge keys; tag/anchor orderings; local/verbatim/custom tags; insufficient `Tag::is_yaml_core_schema()` suffixes; and each accepted literal built-in core tag.
- Duplicate and intentionally distinct keys across explicit/implicit tags, plain/quoted strings without Unicode normalization, alternate numeric spellings, signed zero, infinities, all NaN spellings, nesting, flow/block collections, complex mappings with different entry orders, ordered sequences, and comments.
- Maximum-depth, 256-entry near-equal complex keys prove one-time encoding, the exact stable-merge ordering/counter, deterministic exact semantic-work limit and one-over vectors, final adjacent duplicate scanning, and no partial-map result.
- Arbitrary-precision decimal integers through the scalar cap; integer negative zero; alternate decimal/octal/hex spellings; exact closed-form `S`/`C`/`R` charge vectors for nonzero/all-zero, carry/borrow/cancellation, unequal exponent magnitudes, and radix values with different carry patterns but equal lengths; an all-`F` maximum-source-length hexadecimal scalar must be refused from the pre-conversion `S*S` charge; document numeric-work at the limit and one over; canonical-digit memory at the limit and one over; YAML 1.1 separators and legacy booleans remaining strings; lossless finite floats such as `1.0`/`10e-1`; positive/negative float zero; infinities; NaN; mapping-order-insensitive equality; sequence-order-sensitive equality; and nested unknown mappings/sequences with complex keys.
- Exact/one-over accounting with empty values, complex keys, root depth, decoded versus source scalar length (raw checked before Saphyr), and every collection/node limit.
- An exact-version compile/API test proves that the adapter uses only the allowed `yaml-edit`/rowan calls, including `AstNode::cast`, `Scalar::value`, and `Scalar::as_string`, while mutation APIs remain absent. Reconciliation fixtures prove raw `value()`/source-range equality and decoded `as_string()`/Saphyr equality for escaped double/single quotes and multiline plain/quoted/block scalars. Exact zero-width `SCALAR { NULL "" }` fixtures for omitted keys/values/items match only Saphyr's synthetic `~`, have no replacement range, preserve bytes during an unrelated safe edit, and remain distinguishable from explicit `~` and quoted empty strings. Other fixtures cover nested flow collections, explicit tags, parser normalization or decoder disagreement, deliberately missing/overlapping ranges, payload-to-file rebasing, and multibyte characters before/inside candidate ranges.
- No-op body saves preserve exact bytes/revision/timestamps/tested status. Actual body changes exercise mandatory timestamp/status companions. Golden emitter and replace/add/remove pairs cover scalar quoting/escaping, U+FEFF-as-data, noncharacter rejection, new-document dual reparse/semantic equality, block collections, archive/restore, default-Category clearing, comments on either neighboring entry, key order, prior quote styles, Unicode, BOM, LF/CRLF, and missing final newline.
- Byte-identical refusal for body edits whose mandatory metadata companion is unsafe, a known-collection replacement that would drop an unknown descendant, any undeclared semantic delta, comment-bearing collection/entry replacement, flow-map mutation, ambiguous insertion/removal, semantic/presentation disagreement, overlapping spans, and every unsupported edit.
- Property/fuzz tests for bounded termination, no panic, post-edit semantic intent, reparsing, and outside-span byte identity.

## Consequences

- Reads can remain useful when the presentation layer refuses a safe edit.
- Unknown YAML semantics are not narrowed to JSON or `f64`.
- Two parsers and a reconciliation layer increase implementation/test cost but keep trust decisions in Rehow.
- `yaml-edit` is never treated as a security boundary or serializer.
- Phase 1C may begin only from a reviewed task packet that preserves this ADR's dependency/API limits; the independent security approval gate passed on 2026-09-06.

## Rejected

- `serde_yaml`/`serde_yml`, semantic DOM-only crates, parse-to-struct then serialize, or `yaml-edit` high-level mutation: insufficient preservation and/or validation control.
- `Parser::load` or any unbounded recursive load before Rehow limits.
- A full custom YAML parser/CST: disproportionate risk.
- JSON values, `f64`, or string-key-only maps for unknown YAML: they narrow valid core semantics.
