# Task Packet: Phase 5D3D3 authenticated HTTPS integration

- **Objective:** Let accepted HTTPS clone, sync inspection/history, and exact push use the launch-held credential proxy without exposing credential values or mounting an active Workspace into a network child.
- **Required reasoning level:** xhigh for the credential and process boundary; high for integration.
- **Prerequisites:** Signed Phase 5D3D1 helper provenance and Phase 5D3D2 proxy/resources; accepted anonymous-HTTPS and authenticated-SSH operations in ADR 0025.
- **Allowed files or subsystem:** `crates/rehow-core/src/git.rs`, `git/credential_proxy.rs`, `git/https_credentials.rs`, native Git adapter state, packaged helper smoke script, and aligned Git/security/testing/installation documentation.
- **Relevant specifications and ADRs:** `docs/adr/0025-safe-git-synchronization.md`, `docs/architecture.md`, `docs/testing-strategy.md`, and `docs/threat-model.md`.
- **Exact required behavior:** Retain an immutable kernel-copied snapshot of an exact private owner-held GitHub CLI `hosts.yml` descriptor without parsing it; require it only for the accepted `gh` helper; materialize it read-only at one synthetic path. Model anonymous HTTPS, authenticated HTTPS, and authenticated SSH as closed core transport authority. For authenticated HTTPS, mount only proxy/helper/optional backing descriptors, bind the canonical host including an explicit port, reset all other helpers, and enable the fixed proxy for discovery, fetch/deepening, and push. Native code automatically uses trusted launch provenance and otherwise preserves anonymous HTTPS.
- **Important states and edge cases:** Missing/unsafe proxy or required backing; direct helper with no backing; no configured helper; explicit ports; Git's EOF-terminated credential record; helper failure, 401, timeout, output limit, and wrong host; existing SSH behavior.
- **Security constraints:** No repository-selected helper, prompt, caller command, token/password in Rust results, logging, `Debug`, errors, evidence, renderer IPC, or persistence. No active Workspace mount in discovery/fetch. Push retains exact preflight/refspec/postflight rules. Rehow and its proxy spawn argv directly; Git's internal fixed helper launcher may use `/bin/sh` only for the compile-time absolute proxy path plus Git's closed operation word.
- **Tests to add or update:** Private backing metadata/mount/redaction tests; authenticated command/env/host tests; authentication-error classification; packaged real Git → packaged proxy → canary helper smoke; EOF framing regression; existing SSH loopback and command-surface regressions.
- **Commands to run:** Focused Cargo tests and packaged smoke; strict Workspace Clippy; `pnpm check`; `pnpm test`; production builds only if packaging/build inputs changed.
- **Required reviews and artifacts:** One reused Security Reviewer after the complete gate; no design review because no renderer behavior or geometry changes.
- **Explicit non-goals:** IPv6-literal remote URLs, live credentials, credential prompts, libsecret/D-Bus mediation, token storage, helper installation/configuration, URL-scoped helpers, redirects, scheduled sync, packed-branch publication, or MCP mutation. IPv6 literals remain rejected by the existing conservative remote URL policy.
- **Definition of done:** The three accepted HTTPS network paths consume only the closed authority; anonymous HTTPS still works without a helper; packaged canary and full regression gates pass; one focused Security Review passes; docs match code.
- **Expected commit boundary:** Core/native integration, packaged smoke, packet/evidence, and aligned docs form one signed reviewable checkpoint; Orchestrator owns the commit.
- **Conditions requiring escalation:** Any need to read credential bytes in Rehow, expose a user path, pass user-controlled shell/config text, widen network/repository mounts, weaken TLS, add a dependency, or change push semantics.
