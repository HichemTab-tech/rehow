# Task Packet: safe Git remote connection

- **Objective:** Add one secret-free named HTTPS/SSH remote to the currently open direct Git-backed Workspace through a revision-bound, native-confirmed, crash-resumable config mutation with no network access.
- **Required reasoning level:** xhigh architecture and security boundary; high integration.
- **Prerequisites:** Signed Phase 5A and 5B1 checkpoints; accepted ADR 0021 and Phase 5B2 delta in ADR 0022; retained Workspace capability and Git repository confinement.
- **Allowed files or subsystem:** `crates/rehow-core/src/git.rs`, `crates/rehow-core/src/storage.rs`, `apps/desktop/src-tauri/src/lib.rs`, `apps/desktop/src/App.tsx`, `apps/desktop/src/app.test.ts`, `apps/desktop/src/index.css`, directly applicable Git/security/testing/architecture docs, this packet, evidence, and `PROGRESS.md`. Preserve unrelated `x`.
- **Relevant specifications and ADRs:** `docs/architecture.md` Git boundary; `docs/threat-model.md`; `docs/testing-strategy.md`; ADR 0021; ADR 0022.
- **Exact required behavior:** Validate and canonicalize the ADR 0022 name/URL grammar. Plan against exact bounded config bytes and return only token/name/transport/host. Preserve all pre-existing config bytes and append one canonical remote section. Apply by matching and consuming the native-held token, showing native confirmation, rechecking Workspace/repository/config state, atomically exchanging a durable `config.lock`, validating the displaced before-image/inode orientation, syncing, and moving the lock no-replace to an inert random before-image backup. Refresh displayed Git status after success. Same-request retries recover either interrupted orientation; unrelated locks and same-name remotes fail closed.
- **Important states and edge cases:** HTTPS, SSH URI, SCP syntax; invalid/secret-bearing/ambiguous URLs; invalid names; missing/unsafe/oversized/malformed config; same-name remote; unrelated or partial lock; stale config/root/Workspace; pre-exchange and post-exchange interruption; token mismatch/replay/cancel; read-only Workspace; non-repository/unsafe repository; long UI input and narrow window.
- **Security constraints:** No network or credential code. No remote URL in renderer responses, errors, logs, Debug output, evidence, or status. Root-owned fixed Git only parses a held config in no-include/name-only mode with cleared environment and bounded time/output. No repository-controlled command/config execution. Descriptor-relative no-follow reads/writes; owner-controlled single-link regular files; no overwrite of unrelated lock/config; atomic exchange and directory fsync. Renderer never supplies a path or confirmation.
- **Tests to add or update:** Core grammar/canonicalization, byte preservation, duplicate detection, stale CAS, unsafe files, unrelated lock, exact pre/post interruption recovery, external race rollback, and no-network evidence; native closed/pathless/redacted payloads plus token mismatch/replay/cancel mapping; UI closed payload guards, form normalization/error/busy/status refresh/focus behavior.
- **Commands to run:** Focused Rust and Vitest tests while iterating; then once: `cargo fmt --all --check`, locked full Workspace tests and all-target/all-feature Clippy with warnings denied, `pnpm check`, `pnpm test`, `pnpm build`, `pnpm tauri:build`, bootstrap/contract/whitespace checks.
- **Required reviews and artifacts:** One Security Reviewer/xhigh after implementation; current Web Interface Guidelines static review for the compact form; `docs/evidence/phase-5b2-git-remote-connect.md` with fault/race/redaction results.
- **Explicit non-goals:** Network reachability, fetch, clone, pull/push/sync, credential helpers, SSH agent use, remote update/removal/rename, branch tracking, commit, arbitrary schemes, arbitrary Git config editing.
- **Definition of done:** Behavior and hostile/recovery tests pass; no URL leaks across renderer/error/debug surfaces; config preservation and exact CAS are demonstrated; one security review has no blocker/high/medium finding; full gate passes; signed feature checkpoint and truthful progress ledger exist.
- **Expected commit boundary:** ADR/packet, core storage/domain behavior, native adapter, bounded UI, tests, and evidence in one feature commit; verified progress ledger may follow.
- **Conditions requiring escalation:** A supported URL cannot be represented without weakening the grammar; atomic exchange/fsync is unavailable; unrelated lock/config state cannot be preserved; credentials/network become necessary; repository config could select executable behavior; or a security finding cannot be corrected within this boundary.
