# Task Packet: Phase 5B3A clone tree envelope

- **Objective:** Add a crate-private, deterministic validator that converts one complete `git ls-tree -r -l -z --full-tree` snapshot into an effect-bound list of canonical Rehow materialization entries without adding process, network, filesystem, or adapter authority.
- **Required reasoning level:** xhigh for the accepted boundary; implementation is narrow enough for local Worker/low execution.
- **Prerequisites:** Signed Phase 5B2 checkpoint `33d90fa`; accepted ADR 0023; existing Workspace path/count/byte rules and BLAKE3 dependency.
- **Allowed files or subsystem:** `crates/rehow-core/src/git.rs`, the narrow path-classification bridge in `crates/rehow-core/src/storage.rs`, this packet, ADR 0023, its evidence file, and progress bookkeeping. No adapter/UI/MCP/Cargo/dependency changes.
- **Relevant specifications and ADRs:** `docs/product-spec.md` Git requirements; `docs/content-model.md` v1 structure and limits; `docs/architecture.md` Git boundary; `docs/testing-strategy.md` Git hostile-input gate; `docs/threat-model.md`; ADRs 0021–0023.
- **Exact required behavior:** Accept full lowercase SHA-1 or SHA-256 commit/object IDs; require one object format, strict NUL framing, strictly byte-sorted unique records, exact `100644 blob` type/mode, canonical decimal sizes, a required `rehow.yaml`, and only ADR 0023's five path classes. Enforce the existing per-file, count, managed-byte, and Attachment-byte caps plus a 32 MiB listing cap. Produce a domain-separated plan hash over commit and all path/OID/size tuples. Keep types crate-private and redact paths/OIDs/hash from `Debug`.
- **Important states and edge cases:** Empty/missing manifest; exact/one-over object ID widths; uppercase/nonhex/abbreviated IDs; SHA-1/SHA-256 mismatch; missing/extra/interior NUL; duplicate/unsorted records; zero/leading-zero/overflow sizes; exact/one-over file/count/aggregate limits; Unicode/non-UTF-8/traversal/control/bidi/backslash paths; `.git`, `.gitattributes`, `.gitmodules`, symlink, executable, gitlink, and unknown-root entries.
- **Security constraints:** Treat every byte as hostile. Do not invoke Git, read files, open sockets, accept a caller path, log content, expose a public construction surface, or relax the canonical Workspace scanner. `.gitignore` is the only accepted ancillary root file and remains inert data.
- **Tests to add or update:** Focused unit tests in `git.rs` for valid SHA-1/SHA-256 snapshots, redacted debug, hostile object/path/framing cases, missing manifest, size/count/aggregate bounds, and stable plan hashing. Existing storage tests must remain green.
- **Commands to run:** `cargo fmt --all --check`; `cargo test -p rehow-core git::tests::clone_tree --locked`; `cargo clippy -p rehow-core --all-targets --all-features --locked -- -D warnings`; `python3 scripts/check_bootstrap.py`; `git diff --check`.
- **Required reviews and artifacts:** Evidence file with the exact boundary and focused results. No extra reviewer for this pure non-authority slice; the same code receives the single Phase 5B3 Security Reviewer at the first network/mutation checkpoint.
- **Explicit non-goals:** Remote discovery/fetch, Git subprocesses, credentials, destination selection, blob streaming/content parsing, recovery objects/journals, directory creation, ref/config mutation, Tauri commands, UI, cancellation, or cleanup.
- **Definition of done:** The validator is crate-private, exact behaviors and hostile cases pass, no dependency/API/adapter authority changes, documentation distinguishes completed 5B3A from pending 5B3B/5B3C, and the focused gate is green.
- **Expected commit boundary:** ADR 0023, packet/evidence, path-classification bridge, validator, and tests form one signed feature checkpoint owned by the Orchestrator.
- **Conditions requiring escalation:** Any need for a dependency, public API, altered Workspace grammar/limit, Git execution, credential access, filesystem mutation, or relaxation of the strict accepted file set.
