# Task Packet: Phase 6E3A MCP managed Git commit

- **Objective:** Expose one deliberate, managed-only local Git commit and explicit interrupted-publication recovery through the accepted core plan and sealed native approval boundaries.
- **Required reasoning level:** high implementation; xhigh Security Reviewer gate.
- **Prerequisites:** Signed Phase 5C3 native commit checkpoint; signed Phase 6E1 capability/approval foundation; accepted ADRs 0024, 0026, 0039–0042, and 0047; formal Phase 6E2D correction verdict closed before final integration.
- **Allowed files or subsystem:** `crates/rehow-core/src/git.rs` only for narrow opaque binding/pathless result helpers; `crates/rehow-mcp/`; MCP smoke/API fixtures; Phase 6 Git/security/testing/development docs; evidence and `PROGRESS.md`. Exclusive ownership while implementing.
- **Relevant specifications and ADRs:** Git sections of `docs/product-spec.md`, `docs/architecture.md`, `docs/mcp-spec.md`, `docs/testing-strategy.md`, and `docs/threat-model.md`; ADRs 0021–0024, 0040–0042, and 0047.
- **Exact required behavior:** Add an opaque `gitState` to `git_status`; add `git_commit_plan(handle, expectedGitState, message)`, `git_commit(handle, planToken)`, `git_commit_recovery_plan(handle)`, and `git_commit_recover(handle, planToken)`. Planning requires write+Git-write authority, a trusted approval helper, exact current `gitState`, no existing candidate/recovery, and successful off-thread core planning. Return only normalized message, safe branch, four bounded counts, policy facts, token, and expiry. Execution consumes handle+token once, obtains exact native Git-write approval, refreshes portable Workspace identity, and applies the retained core plan off-thread. Recovery is discovered internally, separately planned/approved, accepts no operation ID, and resumes only the core-selected pending intent. No operation returns paths, OIDs, identity, content, raw Git output, or credentials.
- **Important states and edge cases:** Missing/read-only/no-Git-write Workspace; unavailable helper; stale/forged `gitState`; invalid message; unavailable/unsafe/not-repository Git; detached/advanced/staged/conflicted repository; missing or ambiguous local identity; nothing to commit; staging/resource limit; one-candidate busy state; expiry, replay, wrong Workspace/operation, denial, protocol cancellation before approval or before core publication; repository/Workspace drift after approval; panic/join failure; interrupted publication; recovery no longer required, recovery conflict, and newer Workspace changes after successful recovery.
- **Security constraints:** Never accept Git argv, paths, refs, OIDs, identity, environment, credentials, operation IDs, raw output, or consent assertions. Reuse core descriptor confinement, fixed argv, cleared environment, hook/helper/filter/signing/network exclusion, exact CAS, intent recovery, and unrelated-change preservation. Bind tokens to launch/root/portable Workspace, operation, core effect digest, message, branch/counts, and expiry. One use only. Quarantine only exact held staging. Never push, fetch, reset, clean, checkout, merge, rebase, stash, amend, sign, update reflogs, or delete Git objects.
- **Tests to add or update:** Exact tool/schema count; stable `gitState` and stale-state refusal; startup capability/helper matrix; plan output non-disclosure; normalized-message and core error mapping; successful managed-only commit preserving unrelated tracked/untracked/staged state according to core policy; wrong-scope/replay/expiry/denial/cancellation races; post-approval repository and portable-ID drift; pending-recovery blocking; separately approved recovery success/conflict/no-longer-required; output/debug/log scans for paths/OIDs/credentials/raw Git output; real JSON-RPC lifecycle; strict Clippy.
- **Commands to run:** Focused MCP/core tests and strict package Clippy while coding; one `pnpm check`, `pnpm test`, `pnpm build`, Cargo format, strict workspace Clippy/test, bootstrap, contract drift, and whitespace gate before checkpoint. Do not install or switch Node/pnpm.
- **Required reviews and artifacts:** One Security Reviewer after focused tests pass, covering token/effect binding, cancellation boundary, Git subprocess confinement, staging cleanup, publication/recovery, and disclosure. Add a concise evidence document. No UI/design review because this phase changes no application UI.
- **Explicit non-goals:** Git sync/fetch/pull/push, credentials/authentication prompts, remote editing, signing, reflogs, arbitrary branches/refs/paths/arguments, amend, history UI, scheduled commits, staging cleanup/pruning, desktop changes, dependencies, Workspace schema changes.
- **Definition of done:** The four closed tools work independently of the desktop; only a startup-authorized and natively approved exact plan can publish or recover; all stale/replay/cancellation/conflict cases fail safely; unrelated content remains untouched; focused and full gates pass; Security Reviewer returns PASS; evidence/progress are truthful; signed implementation and progress checkpoints exist.
- **Expected commit boundary:** First commit this ADR/packet as planning only. After the prerequisite verdict, one implementation/docs checkpoint and one optional progress ledger checkpoint; root Orchestrator owns signed commits.
- **Conditions requiring escalation:** Need to expose any forbidden Git/filesystem fact; inability to bind the retained core plan exactly; cancellation could abandon ambiguous active metadata; recovery would require client-selected authority or destructive Git; new dependency; weakened confinement; unresolved Phase 6E2D security verdict; or a genuine human checkpoint.
