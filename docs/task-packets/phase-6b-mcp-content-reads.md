# Task Packet: Phase 6B bounded MCP content reads

- **Objective:** Add independently useful, bounded Category/Guide/search/validation reads and confined refresh to the accepted Phase 6A server.
- **Required reasoning level:** high for schemas, pagination, disclosure, and refresh concurrency.
- **Prerequisites:** signed Phase 6A checkpoint `cb6f7de`; ADRs 0026 and 0027; accepted core Workspace/search/refresh APIs.
- **Allowed files or subsystem:** `crates/rehow-mcp/`; narrow read-only core accessors only if required; MCP/architecture/testing/threat/install/development docs; this packet/evidence; lockfile only if an approved dependency is unavoidable.
- **Relevant specifications and ADRs:** `docs/mcp-spec.md`, ADR 0026, ADR 0027, `docs/content-model.md`, `docs/testing-strategy.md`, and `docs/threat-model.md`.
- **Exact required behavior:** Add exactly `categories_list`, `category_get`, `guides_list`, `guides_search`, `guide_get`, `workspace_validate`, and `workspace_refresh`. Require an exact launch handle for every call. Apply 25-default/100-maximum pagination and strict tool/filter/workspace/view-bound cursors. Preserve deterministic Category order and Guide ordering. Reuse core search ranking and limits. Return typed metadata/revisions/effective status, optional body with 256 KiB default/2 MiB maximum and UTF-8-safe truncation, and bounded fenced-code extraction. Refresh only the retained descriptor-confined view and keep the prior view on failure.
- **Important states and edge cases:** unknown handle/Category/Guide; malformed IDs; zero/over-limit pages and body limits; missing/mismatched/forged/overflow cursor; archived filters; empty filters/results; exact Tag spelling; malformed isolated documents/issues; non-ASCII truncation; oversized/many code blocks; external create/edit/delete before and after refresh; refresh failure; concurrent readers/refresh; poisoned lock; modern and legacy protocol tool schemas/calls.
- **Security constraints:** No arbitrary path, raw YAML/frontmatter, HTML rendering, Attachment bytes, external file reads, mutation, tested transition, Git/process/shell/network, logging, resources/prompts, or runtime root addition. Do not echo invalid handles/cursors/queries in errors. All output fields/counts/arrays/body/code blocks are finite. Treat returned content as untrusted data.
- **Tests to add or update:** exact tool set and schema assertions; pagination/cursor binding and limits; list/filter/order matrices; Guide metadata/body UTF-8 exact/truncation; code-block caps; search ranking/filter/pagination; validation issue pagination; successful/failed external refresh and prior-view retention; unknown/malformed inputs; path/HTML/content instruction labeling; real-binary stdout smoke.
- **Commands to run:** Cargo formatting; focused MCP tests; strict MCP then full-workspace Clippy; `pnpm check`; `pnpm test`; `pnpm build`; bootstrap and whitespace checks.
- **Explicit non-goals:** any content mutation; Attachment transfer; tested approval; Git tools; broad/destructive plans; HTTP/OAuth/network; desktop/UI changes; client configuration edits; normalized Tag-query redesign.
- **Definition of done:** Both protocol lifecycles expose and call the exact nine-tool total surface; bounded reads/search/refresh behave deterministically against temporary Workspaces; hostile inputs fail closed without path/content reflection; full gates and one final reused Security Review pass; docs match code.
- **Expected commit boundary:** ADR/packet, read schemas/handlers/helpers, adversarial tests, evidence, and aligned docs form one signed checkpoint; progress follows separately.
- **Conditions requiring escalation:** core APIs require new write/path authority; response bounds cannot be guaranteed; refresh cannot preserve the prior view; search behavior would be reimplemented divergently; a new dependency or protocol capability expands the trust boundary.
