# Task Packet: Phase 6E3B MCP safe Git synchronization

- **Objective:** Expose deliberate, natively approved `pull`/`push` synchronization and exact interrupted-pull recovery through the accepted Phase 5D core without exposing remote or credential authority.
- **Required reasoning level:** high implementation; xhigh Security Reviewer gate.
- **Prerequisites:** Signed Phase 5D4 and Phase 6E3A checkpoints; accepted ADRs 0025, 0026, 0039–0042, 0047, and 0048; installed Node/pnpm versions remain unchanged.
- **Allowed files or subsystem:** Narrow opaque sync/recovery helpers in `crates/rehow-core/src/git.rs`; structured error helpers in `crates/rehow-core/src/protocol*`; `crates/rehow-mcp/`; Phase 6 Git/security/testing/development/installation docs, evidence, and `PROGRESS.md`. Exclusive ownership while implementing.
- **Relevant specifications and ADRs:** Git sections of `docs/product-spec.md`, `docs/architecture.md`, `docs/mcp-spec.md`, `docs/testing-strategy.md`, and `docs/threat-model.md`; ADRs 0021–0025, 0040–0042, 0047–0048.
- **Exact required behavior:** Add `git_sync_plan(handle, expectedGitState, direction)`, `git_sync(handle, planToken)`, `git_sync_recovery_plan(handle)`, and `git_sync_recover(handle, planToken)`. Direction is exactly `pull` or `push`. Planning requires write+Git-write capability, trusted helper, exact `gitState`, retained recovery storage, and the shared per-Workspace Git reservation. Obtain native approval before network/credential use; denial performs no network. Run accepted authenticated inspection/classification with protocol cancellation. Return only bounded safe facts and an executable token when pull is a clean remote fast-forward or push is local-ahead. Execution consumes handle+token once, obtains a second exact approval, rechecks Workspace identity, and invokes only the accepted core pull or push. Recovery is internally discovered, exact-operation bound, separately approved, pathless, and pull-only.
- **Important states and edge cases:** Read-only/no-Git-write/untrusted-helper; forged/stale state; no repository/upstream; unsafe config/repository; recovery pending; HTTPS anonymous/authenticated and SSH resource preparation; approval denial/cancellation; network timeout/unavailable/authentication/host-key failures; up-to-date; local-ahead; clean/dirty remote fast-forward; diverged/history-limit; opposite direction; plan expiry/replay/scope mismatch; Workspace/repository/remote drift; push uncertain postflight; pull interruption/recovery replacement/conflict; shared commit-vs-sync busy state; server shutdown.
- **Security constraints:** No URL/ref/OID/path/content/identity/credential/raw-output/Git-argv/consent field crosses MCP. Capture provenance only for an explicit Git-write launch. Invoke credentials only after native inspection approval. Use fixed core authentication resources and commands. Never force, reset, clean, checkout, merge, rebase, stash, discard, auto-resolve, install hooks, sign, rewrite history, or select arbitrary refs. Bind tokens to launch/root/portable Workspace, direction, opaque core token, safe plan facts, classification, and expiry. Hold one lifecycle reservation through approval and terminal apply/recovery.
- **Tests to add or update:** Exact forty-three-tool schemas; direction/state validation; startup capability/helper matrix; inspection denial before network; cancellation propagation; safe output/non-disclosure; closed ancestry/direction/action matrix; apply approval/denial/replay/expiry/scope; commit-vs-sync concurrent exclusion; core successful pull/push and hostile remote/auth suites remain green; exact recovery replacement test; stable structured error mapping; real JSON-RPC cancellation; temporary Workspace/repository/state fixtures only.
- **Commands to run:** Focused core/MCP tests and strict package Clippy while coding; once at checkpoint run `pnpm check`, `pnpm test`, `pnpm build`, Cargo format, strict workspace Clippy, bootstrap, contract drift, and whitespace checks. Do not install or switch Node/pnpm.
- **Required reviews and artifacts:** One Security Reviewer after focused tests pass, covering network consent, credential provenance, cancellation, token/classification binding, pull/push confinement, shared lifecycle exclusion, recovery, and disclosure. Add concise evidence. No design review because no application UI changes.
- **Explicit non-goals:** Automatic/scheduled sync, generic fetch/pull/push, arbitrary remotes/branches/refspecs, force, merge/rebase/stash/reset/clean/checkout, conflict resolution, credential entry/storage, remote editing, staging cleanup, signing, desktop UI changes, dependencies, Workspace schema changes.
- **Definition of done:** Four closed tools independently perform only approved exact-direction sync/recovery; network/credentials and mutation each require native approval; non-actionable states cannot mutate; stale/replay/cancellation/concurrency/recovery cases fail safely; outputs remain redacted; focused/full gates and Security Reviewer pass; evidence/progress are truthful; signed implementation and ledger checkpoints exist.
- **Expected commit boundary:** One signed ADR/packet planning checkpoint, then one signed implementation/docs checkpoint and progress ledger. Root Orchestrator owns commits.
- **Conditions requiring escalation:** Any need to expose forbidden remote/Git/credential facts; inability to separate network and mutation approval; cancellation could abandon ambiguous active state; exact recovery binding unavailable; weakened authentication/confinement; new dependency; destructive Git; or a genuine human checkpoint.
