# Task Packet: Phase 6A MCP protocol/startup foundation

- **Objective:** Turn the inert `rehow-mcp` binary into a bounded, separately runnable, read-only stdio MCP server with explicit Workspace allowlisting and setup/health tools.
- **Required reasoning level:** xhigh for stdio/root/handle boundaries; high for implementation.
- **Prerequisites:** ADR 0026; accepted core Workspace inspection; current MCP 2026-07-28 and official Rust SDK 3.4 contracts.
- **Allowed files or subsystem:** Root/Cargo lock manifests, `crates/rehow-mcp/`, the narrow core root-identity comparison API required by launch verification, MCP/development/installation/testing/threat docs, and Phase 6A packet/evidence.
- **Relevant specifications and ADRs:** `docs/mcp-spec.md`, ADR 0026, ADR 0003, `docs/threat-model.md`, `docs/testing-strategy.md`, and `docs/error-contract.md`.
- **Exact required behavior:** Exact-pin audited official `rmcp` 3.4.0 and minimal async/schema dependencies. Serve modern `server/discover` and compatible legacy initialize over newline-delimited stdio. Enforce a 1 MiB frame bound before JSON allocation; stdout is protocol-only. Parse 1–16 repeated `--workspace alias=/absolute/path` arguments with the frozen alias grammar; reject all unknown flags, relative/NUL/non-UTF-8 paths, duplicate aliases, and canonical duplicate/nested/overlapping roots. Canonicalize then core-open and identity-recheck each root. Retain compatible roots under random launch handles. `workspaces_list` returns aliases/handles/portable IDs/compatibility/capabilities without paths. `workspace_get` requires an exact handle and returns bounded manifest/inventory/health/schema/Git-capability summary without Guide bodies, commands, Git output, or absolute paths.
- **Important states and edge cases:** No arguments; help/version; missing/non-directory/non-readable/symlink-raced root; empty/ordinary/unrelated/malformed/newer Workspace; duplicate portable IDs across distinct roots; duplicate/nested roots; 16/17 roots; exact/overlong aliases and frames; LF/CRLF; EOF fragment; invalid JSON/RPC; modern discovery and legacy initialize; unknown/replayed handles; stdout/stderr separation; client disconnect.
- **Security constraints:** No ambient root discovery, cwd default, environment path, runtime root addition, mutation, refresh, body/search, raw Markdown/YAML, arbitrary file/process/shell/network, Git execution, client path, or returned absolute path. Do not log request/tool/content/path/handle bytes. Workspace data is labeled untrusted. Finite frame/output/time/count limits are mandatory.
- **Tests to add or update:** CLI grammar and overlap matrix in temporary directories; identity-race seam; bounded transport exact/one-over/EOF/malformed tests; spawned modern discovery/legacy initialize/tool-list/call/shutdown/stdout-purity tests; deterministic schema snapshots; handle/path redaction; duplicate Workspace ID; every Workspace classification; schema and response bounds; no-mutation byte snapshots.
- **Commands to run:** Dependency/license/advisory audit; Cargo formatting; strict all-target/all-feature Clippy; focused MCP tests; full `pnpm check`/`pnpm test`; production build; standalone EOF/stdout smoke; bootstrap/whitespace checks.
- **Explicit non-goals:** Category/Guide/search/validation pagination; content bodies; resources/prompts; refresh; mutation/capability flags; approval helper; Git tools; HTTP; OAuth; network; subscriptions/tasks; desktop/UI changes; MCP client-config mutation.
- **Definition of done:** Current and legacy clients can discover/list/call the two read-only tools against temporary explicit Workspaces; hostile startup/framing/handle/root cases fail closed; output contains no paths/content leaks; full gates and one Security Review pass; docs match code.
- **Expected commit boundary:** Dependency lock, bounded stdio/startup/server implementation, tests, evidence, and aligned docs form one signed checkpoint; progress follows separately.
- **Conditions requiring escalation:** SDK cannot support both dated protocols; finite framing requires forking SDK internals; root identity cannot be rechecked without exposing path authority; new network/process capability appears; dependency audit fails; mutation or approval is required.
