# Task Packet: Recoverable Git commit publication

- **Objective:** Publish one still-current Phase 5C1 candidate by append-only object installation followed by recoverable index/direct-branch-ref compare-and-swap, without committing unrelated changes or writing reflogs.
- **Required reasoning level:** xhigh.
- **Prerequisites:** Signed Phase 5C1 checkpoint `4ffc4f8`; accepted ADRs 0009, 0021, and 0024; retained direct repository capability; opaque `GitCommitPlan` with verified staging snapshot.
- **Allowed files or subsystem:** `crates/rehow-core/src/git.rs`; narrowly required private Git metadata and recovery primitives under `crates/rehow-core/src/storage.rs` and `storage/recovery/`; focused tests; ADR 0024 evidence; `PROGRESS.md`. No desktop, React, MCP, Workspace-content mutation, dependency, or contract changes.
- **Relevant specifications and ADRs:** Git sections of `docs/product-spec.md`, `docs/architecture.md`, `docs/testing-strategy.md`, `docs/threat-model.md`; ADRs 0009, 0006, 0021, and 0024.
- **Exact required behavior:** Under the cooperating writer lock, consume one plan; verify its token/staging identity/snapshot and repeat every bound Phase 5C1 repository, Workspace, branch-representation, index, marker, identity/config, and managed-effect check. Pack exactly the candidate-created object closure in private staging using fixed config-free plumbing; independently validate pack/index checksums, object count/types/OIDs, and candidate reachability. Install immutable pack/index files into the retained active object-store `pack/` directory using descriptor-relative no-follow no-replace publication or accept only byte-identical existing files; sync files and parents and never delete object data. Create a distinct operation-bound `GitCommit` recovery intent containing exact before/candidate index and direct loose-ref states. Generate an ordinary stage-zero index for the candidate tree in private staging with extensions stripped and prove `write-tree == candidate tree`. Publish index first and loose branch ref last with exact before-state CAS. For a packed branch, create a loose shadow only while unchanged `packed-refs` still resolves the planned parent; never rewrite `packed-refs`. For unborn, require exact loose/packed absence. Never open or write reflogs. After durable ref publication, replay only forward; before ref publication, a ref-CAS loss may restore only the exact candidate index to its exact saved before-image. Foreign index/ref state is preserved and reported as conflict. Verify final branch, index tree, candidate tree, and fresh managed effects. Quarantine retained staging after successful completion; leave installed unreachable objects harmless after later refusal.
- **Important states and edge cases:** SHA-1/SHA-256; unborn, loose, and packed direct branches; existing identical pack; pack-name collision; missing/corrupt candidate object; stale Workspace/root/Git/config/index/ref/packed-refs/marker state; index publication interruption; ref publication interruption; ref race after index; foreign index/ref during replay; crash after durable ref but before intent completion; candidate staging mutation; permission/durability failure; object quota and deadline exhaustion.
- **Security constraints:** Descriptor confinement and no-follow types for every active path; root-owned Git/Bubblewrap with cleared environment and fixed argv; no shell, hooks, filters, attributes, signing, helpers, credentials, network, aliases, editors, pagers, arbitrary refs, reflogs, or path/content/OID disclosure. Object installation is append-only; no rollback deletion. Metadata writes use same-directory private temps, exact before-images, durable syncs, and no-replace/exchange primitives. Redacted errors/debug only.
- **Tests to add or update:** Valid SHA-1/SHA-256 loose/packed/unborn publication; unrelated worktree/index protection; exact pack closure and independent OID verification; identical pack resume and collision refusal; every stale binding; cache-tree/advanced index refusal; candidate snapshot mutation; all index/ref intent interruption points; ref-race exact index restoration; foreign-state preservation; ref-durable forward-only replay; no reflog creation/change; no hooks/config/network canaries; status/recovery-required behavior; source audit forbidding active-object deletion and porcelain commit/add/update-ref.
- **Commands to run:** Focused publication/replay tests while coding; `cargo fmt --all --check`; locked core all-target/all-feature Clippy with warnings denied; one full locked all-feature core test gate; bootstrap and whitespace checks.
- **Required reviews and artifacts:** Update Phase 5C evidence. Use zero extra agents during routine work and one reused Security Reviewer/xhigh only after the complete 5C2 implementation is green.
- **Explicit non-goals:** Native confirmation/UI, renderer IPC, MCP commit, reflogs, signing, push/fetch/pull/sync, remote auth, merge/rebase/conflict resolution, cleanup/pruning, arbitrary branch selection, portable Workspace writes, dependency changes.
- **Definition of done:** Exact candidate objects are append-only installed; index/ref-last intent survives and safely classifies every interruption; stale/foreign states never overwrite user bytes; no unrelated change is committed; no reflog or active Workspace byte changes; required tests/review/evidence pass; signed checkpoint and exact restart state exist.
- **Expected commit boundary:** One packet checkpoint if useful; implementation may use a 5C2A append-only-pack checkpoint and a 5C2B index/ref recovery checkpoint, followed by a progress ledger commit. The Orchestrator owns commits.
- **Conditions requiring escalation:** Any need to delete active objects, rewrite `packed-refs`, open/write reflogs, accept an ambiguous index/ref state, weaken exact CAS/durability, add a dependency, expose path/OID/content, run repository-selected code, or broaden into network/native/MCP authority.
