# Task Packet: Native confirmed clone validation

- **Objective:** Connect the accepted anonymous-HTTPS staging pipeline to a single-use, native-confirmed, cancellable desktop command that retains an opaque validated clone session without modifying the selected destination.
- **Required reasoning level:** high.
- **Prerequisites:** Signed checkpoints `1c555f5` and `b14c0f0`; accepted ADR 0023; retained empty-folder capability and native confirmation patterns.
- **Allowed files or subsystem:** `crates/rehow-core/src/git.rs`, `apps/desktop/src-tauri/src/lib.rs`, this packet, focused evidence, ADR 0023, and progress bookkeeping. Exclusive ownership; no React, MCP, storage-format, or materialization changes.
- **Relevant specifications and ADRs:** Git/onboarding sections in `docs/product-spec.md`, `docs/architecture.md`, `docs/threat-model.md`, and ADR 0023.
- **Exact required behavior:** Consume only a matching pending token; reject non-HTTPS transport in this slice; show a parented native confirmation containing the exact already-validated secret-free URL; run discovery/staging/fetch/tree/content validation off the UI thread; expose a pathless cancellation command backed by one active atomic flag; retain the empty destination capability plus opaque validated staging session on success; restore the selected empty capability after a failed/cancelled run; return only closed stage/Boolean payloads and content-free errors.
- **Important states and edge cases:** Missing/mismatched/replayed plan, declined confirmation, no selection, concurrent apply, cancellation before/during each process, changed destination, unavailable Git/Bubblewrap/state root, network/advertisement/repository/Workspace failure, interrupted staging residue, and poisoned state locks.
- **Security constraints:** No renderer path, URL response, OID, ref, filename, content, stderr, staging location, credential, or arbitrary cancellation handle. Confirmation is native and out-of-band. No destination write, checkout, shell, helper, SSH, credential lookup, deletion, or residue cleanup. One live operation maximum; selection changes are refused while active.
- **Tests to add or update:** Core orchestration success/pre-cancel/destination-drift mapping with isolated Git fixtures; native payload/error/confirmation closure, single-use token, active-operation and cancellation-state helpers; compile proof that the opaque session can cross the blocking boundary.
- **Commands to run:** Focused core clone and desktop Rust tests; locked all-target/all-feature Clippy for both crates; Cargo formatting; then one full relevant core/desktop gate, bootstrap validation, and whitespace check at checkpoint.
- **Required reviews and artifacts:** Reuse the single Phase 5B3 Security Reviewer only if this adapter introduces a new unresolved authority finding; otherwise record the already accepted core boundary and focused native evidence.
- **Explicit non-goals:** React onboarding controls, SSH, credential helpers, destination materialization, Git config/ref installation, commit/pull/sync, staging cleanup/quarantine, MCP, or opening the validated Workspace.
- **Definition of done:** Native confirmation/apply/cancel commands are registered, opaque success state is retained, failures preserve the empty destination, tests/gates pass, docs reflect reality, and a signed checkpoint exists.
- **Expected commit boundary:** Public opaque core orchestration plus native state/commands/error mapping/tests and aligned documentation. Orchestrator owns the commit.
- **Conditions requiring escalation:** Need to expose a path/URL/credential to the renderer, inability to safely retain/restore the destination capability, destructive cleanup, overlapping selection mutation, or an unsupported cross-thread native capability.
