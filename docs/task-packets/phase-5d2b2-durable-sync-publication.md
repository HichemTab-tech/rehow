# Task Packet: Durable remote-fast-forward publication

- **Objective:** Compose the accepted journaled Workspace materializer with append-only incoming object installation and exact index/direct-ref publication under one durable sync intent.
- **Required reasoning level:** xhigh because this coordinates two independently durable stores and direct Git metadata publication.
- **Prerequisites:** Signed Phase 5D2B1 checkpoint `85b835b`; ADRs 0009, 0024, and 0025; proven clean `remoteFastForward` authority; accepted commit metadata publisher.
- **Allowed files or subsystem:** `crates/rehow-core/src/git.rs`, `storage.rs`, `storage/recovery.rs`, `storage/recovery/store.rs`, focused ADR/testing/implementation evidence, and progress. No adapters, UI, MCP, dependencies, credentials, push, or scheduling.
- **Relevant specifications and ADRs:** Git/recovery sections of `docs/architecture.md`, `docs/threat-model.md`, and `docs/testing-strategy.md`; ADRs 0009, 0024, and 0025.
- **Exact required behavior:** Revalidate the exact classification and staged tree; generate and independently validate the remote index; append verified pack/index pairs without replacement; durably bind root/Git identities, exact before/candidate index/ref bytes, unchanged `HEAD`/config/packed-refs, remote tree, Workspace journal plan, and branch representation before Workspace mutation; resume Workspace publication before index-first/ref-last publication; require exact candidate Workspace/index/ref state before completion.
- **Important states and edge cases:** No portable byte change with a new commit; interruption before/after intent, journal activation, Workspace completion, index exchange, ref publication, and completion; direct loose branches; packed-only branches fail closed until strict reopen semantics are separately accepted; SHA-1 plus width-generic SHA-256 validation (a full SHA-256 sync fixture may follow); object collision; staging drift; local metadata/content drift; journal conflict; index/ref races; lock residue; already-installed identical packs; foreign before/candidate states.
- **Security constraints:** Retained capabilities only; no shell, checkout, reset, merge, rebase, clean, stash, reflog write, hook, helper, filter, pager, editor, or arbitrary ref; append-only objects; exact no-replace-or-identical verification; journal intent must precede active Workspace mutation; direct expected-state CAS; no automatic conflict resolution or rollback over foreign state; redacted errors and Debug.
- **Tests to add or update:** Intent codec/generation/path/mode bounds; complete fast-forward publication with exact clean index/ref/Workspace and unchanged config/HEAD/packed-refs; all six accepted Git metadata interruption seams plus the existing Workspace journal replay matrix; no-change Workspace commit; packed-only refusal; object/index/ref/journal drift and replacement races; redaction; existing commit and Workspace recovery suites. Full packed publication and a complete SHA-256 sync fixture are explicit follow-ups, not acceptance claims for this slice.
- **Commands to run:** Focused sync/recovery tests while editing; `cargo fmt --all --check`; strict all-Workspace/all-target/all-feature Clippy; `cargo test --workspace --all-features`; bootstrap and whitespace checks.
- **Required reviews and artifacts:** One reused Security Reviewer at the completed cross-store authority gate; focused evidence document.
- **Explicit non-goals:** Native/renderer workflow, merge/rebase, push, remote-tracking ref updates, credentials, authenticated transport, scheduling, MCP mutation, reflogs, pruning retained staging/orphan objects, or general Git recovery UI.
- **Definition of done:** The internal apply/recovery boundary is interruption-safe, exact-state checked, conflict-preserving, fully tested, security-reviewed, documented, and still unavailable to adapters.
- **Expected commit boundary:** One core/docs implementation checkpoint followed by a progress ledger.
- **Conditions requiring escalation:** Any need to overwrite foreign state, publish a ref before durable Workspace completion, depend on the original staging after intent installation, execute repository-selected code, weaken confinement, or introduce rollback that could discard user changes.
