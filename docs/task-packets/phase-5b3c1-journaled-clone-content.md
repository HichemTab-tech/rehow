# Task Packet: Journaled clone content materialization

- **Objective:** Publish an already validated clone snapshot into its still-bound destination through one recoverable `GitMaterialize` journal, while retaining a marker-bound private Git scaffold for the later ref-installation slice.
- **Required reasoning level:** high.
- **Prerequisites:** Signed checkpoint `2812c49`; accepted ADR 0023; recovery journal and descriptor-confined mutation boundaries.
- **Allowed files or subsystem:** `crates/rehow-core/src/git.rs`, `crates/rehow-core/src/storage.rs`, `crates/rehow-core/src/storage/recovery.rs`, `crates/rehow-core/src/storage/recovery/{store,workspace}.rs`, ADR 0023, this packet, focused evidence, and progress bookkeeping. No React or MCP changes.
- **Relevant specifications and ADRs:** ADRs 0009 and 0023; Git, recovery, and confinement sections of `docs/architecture.md`, `docs/testing-strategy.md`, and `docs/threat-model.md`.
- **Exact required behavior:** Re-read every validated staging file through no-follow descriptors; store exact bounded bytes as recovery objects; construct one `GitMaterialize` journal whose complete target set expects absence; revalidate the selected destination; create an exact private `.git/rehow-clone` marker/scaffold; durably install the journal before creating the proven Category/Attachment directory skeleton; resume the normal journal state machine; reopen with the canonical scanner and require the same Workspace identity, revisions, inventory, and Attachment health as the validated view.
- **Important states and edge cases:** Empty first attempt, exact marker/journal resume, foreign destination entry, symlink/special/hardlinked staging file, changed bytes/size, duplicate or reordered target, `.gitignore`, empty directory skeleton, journal interruption, target collision, malformed/oversized journal, scanner mismatch, and recovery lock contention.
- **Security constraints:** No renderer input or output, network, Git child, checkout, credential, deletion, overwrite, arbitrary path, or shell. Only paths from the accepted clone tree are materialized. All targets use `0600`; directories use `0700`. Unknown residue is preserved and causes conflict. Marker and journal bind operation ID, destination identity, and tree plan hash.
- **Tests to add or update:** Journal codec exact/one-over bounds and `.gitignore`; successful multi-directory materialization; exact resume after interruption; foreign-entry and target-collision refusal; staging change/symlink/hardlink refusal; canonical post-scan equivalence; no overwrite.
- **Commands to run:** Focused Git/recovery tests; locked core Clippy with warnings denied; Cargo formatting; one full core gate, bootstrap validation, and whitespace check at checkpoint.
- **Required reviews and artifacts:** Focused evidence plus one reused Security Reviewer only after the complete authority-bearing slice is green.
- **Explicit non-goals:** Git object-pack transfer, config/HEAD/ref installation, React onboarding controls, authenticated transports, cleanup/quarantine, commit, pull, sync, or MCP.
- **Definition of done:** Validated portable Workspace files are journaled, recoverable, canonically rescanned, and proven equivalent without finalizing the Git repository; tests and review pass; a signed checkpoint exists.
- **Expected commit boundary:** Core storage/journal/materialization implementation, tests, packet, ADR status delta, and evidence. Orchestrator owns the commit.
- **Conditions requiring escalation:** Need to relax path confinement, overwrite unknown state, expose authority to the renderer, accept a non-recoverable partial state, or change canonical Workspace limits.
