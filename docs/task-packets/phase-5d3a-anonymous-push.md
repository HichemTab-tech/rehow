# Task Packet: exact anonymous-HTTPS push

- **Objective:** Let the native Reference Desk publish one already-classified `localAhead` commit through a normal, exact-refspec anonymous-HTTPS push without exposing Git authority to the renderer.
- **Required reasoning level:** high.
- **Prerequisites:** ADR 0025 gates 5D1–5D2D; accepted Git capability/sandbox boundaries in ADRs 0021–0024; a retained `GitSyncClassification` produced by the existing pathless sync inspection.
- **Allowed files or subsystem:** `crates/rehow-core/src/git.rs`, `crates/rehow-core/src/lib.rs`, `apps/desktop/src-tauri/src/lib.rs`, `apps/desktop/src/{App.tsx,lib/native.ts,lib/native.test.ts}`, related focused tests, ADR 0025, architecture/testing docs, evidence, and `PROGRESS.md`. No dependency or schema changes.
- **Relevant specifications and ADRs:** `docs/product-spec.md` Git requirements; `docs/architecture.md` Git process policy; `docs/threat-model.md` Git/credential threats; ADRs 0021, 0023, 0025; `docs/testing-strategy.md` Phase 5D requirements.
- **Exact required behavior:** Only an opaque `localAhead` classification can plan/apply push. Core revalidates all local state, rediscovers the exact configured upstream, refuses any remote change, runs a normal explicit `<local-oid>:<remote-ref>` push, then rediscovers and requires the remote to equal the local commit. Native consumes the existing token once, displays a parented confirmation using bounded remote/branch/transport/host labels, and reports a closed result. The UI offers Push only for `localAhead`, handles decline/error/busy/focus/live state, and refreshes Git status after success.
- **Important states and edge cases:** wrong/replayed token; non-`localAhead`; local repository/config/Workspace drift; remote changed or deleted; server rejection; timeout/output cap; unavailable Git/Bubblewrap/network; decline; Workspace switch during publication; successful publication followed by unverifiable remote state.
- **Security constraints:** Anonymous canonical HTTPS only. No force/lease/delete/wildcard/mirror/tags/options; no caller refspec/URL/OID/path; no shell; no repository/user/system/includes config, hooks, helpers, askpass, proxy, redirects, filters, submodules, or writable Workspace mount; bounded output/time; no raw Git output or secrets in public values/Debug/IPC. Publication is not cancellable after confirmation.
- **Tests to add or update:** Core tests for closed/opaque authority, local-ahead-only enforcement, exact remote preflight, command/environment/refspec policy, state drift, remote race/failure mapping, and successful postflight. Native tests for token consumption, confirmation decline, closed error mapping, lifecycle/workspace-switch exclusion, and result shape. UI tests for Push visibility, invocation, success/error, focus, and status refresh.
- **Commands to run:** focused Cargo tests for push; desktop Rust tests; focused Vitest; `cargo fmt --all --check`; `cargo clippy -p rehow-core -p rehow-desktop --all-targets --all-features --locked -- -D warnings`; `pnpm check`; `pnpm test`; `pnpm build`; bootstrap/contract/whitespace checks applicable to changed files.
- **Required reviews and artifacts:** One Security Reviewer at the completed authority gate. No screenshots unless layout changes materially.
- **Explicit non-goals:** Credential-helper or SSH-agent support; scheduled/start sync; packed-only local branch publication; force semantics; multi-ref/tag push; credential prompts/storage; arbitrary transport; MCP Git mutation.
- **Definition of done:** A user can inspect a `localAhead` anonymous-HTTPS upstream, confirm Push, publish exactly the bound commit, receive a verified success, and cannot cause any other ref/URL/OID/path/process behavior. Focused and standard gates pass, security review has no blocker/high/medium finding, docs and progress match actual state, and a signed checkpoint exists.
- **Expected commit boundary:** Core/native/UI anonymous push plus focused tests and truthful gate documentation form one implementation commit; the Orchestrator owns it. A subsequent progress-only commit may record verified commit identity.
- **Conditions requiring escalation:** Any need for force semantics, renderer Git authority, credentials, new dependencies, writable repository exposure to a network child, raw Git output, ambiguous remote acceptance, or a security finding that cannot be corrected within this boundary.
