# Task Packet: Native-confirmed managed Git commit

- **Objective:** Let a user review and deliberately publish one managed-only Git commit from the open Workspace, and explicitly resume an interrupted publication, without exposing filesystem paths, object IDs, content, or Git output to the renderer.
- **Required reasoning level:** high for the native lifecycle and recovery boundary; medium for the bounded Reference Desk UI.
- **Prerequisites:** Signed Phase 5C1/5C2 checkpoints `4ffc4f8` and `bdc43a9`; accepted ADR 0024; retained open-Workspace capability; core candidate planning, cancellation, publication intent, pending-intent detection, and replay.
- **Allowed files or subsystem:** Public pathless wrappers in `crates/rehow-core/src/git.rs`; `apps/desktop/src-tauri/src/lib.rs`; `apps/desktop/src/App.tsx`, `index.css`, and `app.test.ts`; focused evidence/docs and `PROGRESS.md`. No MCP, sync, clone transport, dependency, Workspace-format, generated-contract, or packaging changes.
- **Relevant specifications and ADRs:** Git sections of `docs/product-spec.md`, `docs/architecture.md`, `docs/testing-strategy.md`, and `docs/threat-model.md`; ADRs 0010, 0021, 0022, and 0024; `docs/design-direction.md`; current project-pinned web-design guidelines.
- **Exact required behavior:** Core exposes consuming apply and pathless pending-recovery wrappers; no operation ID leaves core. The native lifecycle permits one planning/apply/recovery operation and at most one pending plan. Planning accepts only a commit message for the currently open writable Workspace, replaces an older pending plan only by identity-safe quarantine, runs off the UI thread, and returns only token, safe branch, managed create/update/delete counts, and unrelated-change count. Apply consumes only the matching token, displays a parented native confirmation containing the exact normalized message and plan facts plus unsigned/no-push/no-network policy, and quarantines on decline. Confirmed publication runs off the UI thread; once an intent begins it is not cancellable. Status reports `recoveryRequired` without an operation identifier when a non-complete intent exists. Explicit recovery uses the internally discovered intent, shows a parented native confirmation, runs off-thread, and returns only completion and whether newer Workspace changes remain. Successful apply/recovery refreshes Workspace and Git status; no plan is reusable.
- **Important states and edge cases:** Invalid/boundary message; missing/read-only/changed Workspace; no repository; detached/unsafe/advanced/staged/conflicted/nothing-to-commit repository; missing/ambiguous identity; planning replacement/cancellation failure; wrong/reused token; decline; plan stale after review; panic/join failure; pending intent at launch/status; successful replay with or without newer Workspace edits; replay conflict; status refresh failure; concurrent native lifecycle action; panel close during plan review; narrow window and long safe branch/message.
- **Security constraints:** Renderer sends only message or plan token. It never supplies a path, branch, counts, status, object ID, operation ID, approval Boolean, Git arguments, or recovery target. Native state owns plans and busy state. Native confirmation is mandatory for publication and recovery. Core remains descriptor-confined, hook/helper/filter/signing/network free, and exact-CAS/replay authoritative. Errors and Debug stay path/content/OID/Git-output free. Decline/cancel never deletes staging by name.
- **Tests to add or update:** Core consuming apply/recovery wrapper success and pending recovery semantics; native closed payload serialization, exact confirmation copy, complete error mapping, token mismatch/one-use behavior, lifecycle busy/restore helpers, and command source audit; React closed payload guards, message normalization, recovery status labeling, plan/apply/recovery state helpers, accessible form/panel static markup, and invalid extra-field rejection. Reuse the accepted core interruption suite rather than duplicating filesystem cases in desktop tests.
- **Commands to run:** Focused core/native/Vitest tests while coding; `pnpm check`; `pnpm test`; `cargo fmt --all --check`; locked core/desktop all-target/all-feature Clippy with warnings denied; locked core/desktop tests; `pnpm build`; optimized Tauri no-bundle build; bootstrap, contract drift, and whitespace checks.
- **Required reviews and artifacts:** Apply the freshly fetched web-design guidelines to `App.tsx`/`index.css`. Use zero extra agents during routine work and at most one reused reviewer after the combined native/UI gate is green. Existing Reference Desk geometry may reuse prior representative screenshots only if this bounded bottom panel is verified at wide and narrow sizes; otherwise capture updated states.
- **Explicit non-goals:** Git sync/push/pull/fetch; authenticated clone; signing; reflogs; arbitrary branch/ref choice; commit history browser; amend; author override; automatic/scheduled commits; MCP mutation; cleanup/pruning; cancellation after durable intent creation; dependencies.
- **Definition of done:** A ready repository can plan, review, confirm, and publish exactly one managed-only unsigned commit; decline/cancel consumes the plan without active Git mutation; interrupted publication is visible and explicitly replayable without renderer-selected recovery authority; pathless closed IPC and concurrency tests pass; focus/error/busy/narrow UI behavior passes the current design rules; required build/test/security gates pass; signed checkpoint and exact restart state exist.
- **Expected commit boundary:** One implementation checkpoint for the core/native/UI slice plus a progress ledger commit. The root Orchestrator owns both signed commits.
- **Conditions requiring escalation:** Any need to expose a path/OID/operation ID/content/Git output; bypass native confirmation; weaken plan consumption, recovery replay, or confinement; add cancellation after durable intent creation; add a dependency; broaden into sync/auth/MCP; or mutate overlapping user files.
